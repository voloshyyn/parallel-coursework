# Deployment

## Стандартний запуск

`docker compose up --build -d` збирає і запускає сервер. Не потрібні ручні
завантаження книг, pip, підготовка data/raw або POST /api/index. Першій збірці
потрібна мережа для базових образів та C++-залежностей. Корпус генерується
офлайн Python stdlib при першому старті, потім автоматично індексується.

Профіль full (типовий): 12 000 документів, >=2 GiB реального UTF-8 тексту.
Профіль demo: 60 документів; лише для швидкої демонстрації, не для атестації
обсягу чи вимірювань масштабування. `DATASET_PROFILE=demo` обирає demo;
у PowerShell задайте `$env:DATASET_PROFILE = 'demo'` перед запуском Compose.

Генератор пише у staging-каталог на тому самому filesystem і перейменовує його
в `/data/generated/<profile>` після завершення та запису manifest. Named volume
змонтовано в батьківський `/data/generated`, а не в каталог, що перейменовується.
Власник створеного тому — непривілейований користувач app. Непорожні чужі дані
не замінюються; невідповідний manifest спричиняє зрозумілу помилку. Для іншого
seed/версії виберіть новий каталог/том. `DATASET_VERIFY_HASH=true` додатково
перевіряє SHA-256; звичайне повторне використання перевіряє імена, кількість,
загальний розмір, seed, профіль і версію.

## Готовність і час

Генерація передує HTTP: дивіться `docker compose logs -f server`. Після запуску
бінарника `/api/health` повертає фіксовані status/ollama. Додатковий `/api/ready`
повідомляє index_state/search_ready/index_error. UI показує побудову індексу,
потім автоматично дозволяє пошук. Docker healthcheck перевіряє доступність HTTP;
для готовності пошуку використовуйте `/api/ready` або `scripts/smoke.sh`.

Контрольний синтетичний корпус (22.11.2026): 12 000 документів,
2 462 028 386 байтів, seed=20240517, SHA-256
`6bf997ceac0124e0fdd7f8de32209611d24372cc64bdedff24fee11d7ef8637f`.
Генерація у Linux-контейнері: 110,23 с; повторне використання: 0,307 с;
повна SHA-256-перевірка: 3,38 с. Це одинична перевірка запуску, не експеримент
масштабування; час залежить від CPU, диска та паралельного навантаження.
Індекс зберігається в RAM та перебудовується після кожного перезапуску сервера.
У контрольному запуску автоматична індексація повного корпусу чотирма потоками
зайняла 23,217 с; `/api/stats` повернув рівно 12 000 документів (manifest
не індексувався).

Синтетичні документи містять різні теми, довжини й частоти слів, але не є
природними книгами. Не можна переносити висновки про якість пошуку/швидкодію
цього корпусу на Gutenberg без окремих вимірювань. Відомі тестові запити записані
в manifest.json (наприклад coral reef, quantum physics, ancient rome).

## Зовнішній корпус

Задайте EXTERNAL_DATASET_PATH абсолютним шляхом до каталогу .txt і виконайте:

```bash
docker compose -f docker-compose.yml -f docker-compose.external.yml up --build -d
```

Override встановлює GENERATE_DATASET=false, DATA_DIR=/data/external та монтує
каталог read-only. Індексатор читає лише `.txt`, не manifest/тимчасові файли.
Старий `tools/prepare_dataset.py` залишається для локально наявного Gutenberg.

## Ollama

Не входить до критичного шляху готовності. Для LLM:
`docker compose --profile llm up -d`, потім
`docker compose exec ollama ollama pull qwen2.5:1.5b`.
Модель зберігається в `ollama_models`; keyword-пошук працює без неї.
Змінні OLLAMA_URL/OLLAMA_MODEL задають сервер і модель. Health показує
доступність Ollama, але не гарантує, що модель уже завантажена.
