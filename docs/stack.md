# Stack

Для вступу звіту потрібен опис обраних технологій з обґрунтуванням. Усі технологічні рішення зафіксовано.

## Обмеження з завдання
- Бекенд: компільована мова — **C++, Java або C#**.
- Інвертований індекс і thread pool — **власна реалізація** (готові `ConcurrentHashMap`-подібні пули/ExecutorService як пул не підходять; для індексу готові контейнери бібліотеки — лише як примітиви під власною структурою, узгодити з викладачем).
- Клієнти: будь-які два різні підходи (веб і консольний).
- Розгортання: Docker Compose, сервіси сервера та Ollama.

## Вибір

| Область | Рішення | Обґрунтування |
|---|---|---|
| Мова бекенду | **C++20** | Обрано. Повний контроль над потоками, пам'яттю та атомиками (`std::thread`, `std::mutex`, `std::shared_mutex`, `std::atomic`); ThreadSanitizer для пошуку гонок |
| HTTP/WebSocket | Crow (пропозиція; альтернативи: Boost.Beast, Drogon) | REST і WebSocket в одному процесі, невелика кількість коду. Підтвердити після прототипу `/api/health` |
| HTTP-клієнт до Ollama | cpp-httplib (пропозиція) | Простий синхронний POST на `/api/generate` |
| JSON | nlohmann/json | Стандарт де-факто, зручний API |
| Збирання | CMake + FetchContent/vcpkg | Залежності підтягуються при збиранні в Docker |
| Тести | GoogleTest + ThreadSanitizer | Юніт + стрес-тести конкурентності |
| Форматування | clang-format (стиль Google) | Див. `conventions.md` |
| LLM | Ollama, `/api/generate` | Локальний запуск за вимогою завдання |
| Модель | Мала, 1–3B (конкретну назву уточнимо при першому запуску) | Швидка відповідь на CPU, достатня для синонімів |
| Web UI | Vue 3 (через CDN, без збирання) | Легкий фреймворк; список результатів і етапів реактивно оновлюється; WebSocket — нативний API браузера |
| CLI | C++, окрема програма `search` | Та сама мова, без додаткових залежностей; JSON через nlohmann/json; `./search "запит"` |
| Контейнеризація | Docker, Docker Compose | Вимога завдання |
| VCS | Git + GitHub | Вимога завдання |
| Форматування | Google Style Guide, автоформатер | Див. `conventions.md` |
