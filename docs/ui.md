# UI

Два клієнти з різними підходами: консольний (CLI) і веб (Web UI). Обидва використовують контракт з `api.md`.

## CLI

```bash
./search "запит"
```

- Викликає `POST /api/search` (`mode=keyword`) і друкує результати.
- Формат рядка: `<n>. <doc_id>  score=<0.95>  <snippet>`; в кінці `time_ms`.
- Адреса сервера: змінна середовища `SEARCH_URL` (за замовчуванням `http://localhost:8080`).
- Помилки (сервер недоступний, індекс не побудований) — зрозуміле повідомлення в stderr і ненульовий код виходу.
- Порожній результат — повідомлення «нічого не знайдено».
- Стрімінг через WebSocket у CLI не реалізуємо (пропущено як опційне).

## Web UI

Мінімальний інтерфейс (вимога: форма пошуку, результати, візуалізація етапів через WebSocket).

### Елементи
1. Поле запиту і кнопка «Шукати» (Enter також запускає пошук).
2. Панель етапів пайплайну: `query_expansion` → `keyword_search` → `done`.
   - стан кожного етапу: очікування / виконується / готово / помилка;
   - після `query_expansion` показати оригінальний запит і розширені терміни;
   - після `keyword_search` показати `time_ms`.
3. Список результатів: `doc_id`, `score`, `snippet`.
4. Індикатор стану сервера (за `/api/health`, включно з `ollama`).
5. Кнопка індексації у Web UI не реалізується в MVP (пропущено як опційне). Індексацію запускаємо через `curl`.

### Стани
| Стан | Поведінка |
|---|---|
| Початковий | Порожня форма, етапи неактивні |
| Пошук | Кнопка заблокована, етапи оновлюються по мірі повідомлень |
| Результати | Список + час |
| Порожньо | Повідомлення «нічого не знайдено» |
| Помилка | Повідомлення з причиною (сервер недоступний, індекс не побудований, обрив WebSocket) |

### Технічно
- Підключення до `ws://<host>/ws/search`, відправка `{ "query": "..." }`, обробка повідомлень за полем `stage`.
- При обриві з'єднання — повідомлення користувачу, без нескінченних перепідключень.
- Статичні файли віддає той самий `server`, щоб запуск лишався однією командою.
- Екранувати snippet перед вставкою в DOM (захист від XSS).
