# Перевірка виправлень етапів 5–7

Дата: 22.11.2026. Linux у Docker Desktop; генератор Python 3.12, Node 18,
GCC 13.3. Паралельні збірки впливали на навантаження; наведені часи —
контроль запуску, не лабораторні результати масштабування.

- Debug: 130/130 CTest-перевірок, включно з поведінковими Node/Python suites.
- ThreadSanitizer, RelWithDebInfo: 130/130; повідомлень про data race немає.
  Використано `TSAN_OPTIONS=halt_on_error=1`, `setarch x86_64 -R` і
  `--security-opt seccomp=unconfined` лише в ізольованому тестовому контейнері.
  GCC повідомляє про обмеження інструментації atomic_thread_fence у сторонній
  Asio; відсутність runtime-повідомлень не є доказом відсутності всіх гонок.
- Відтворюваний Docker target test: 130/130, 4,30 с у контрольному прогоні.
- Реальний браузер на фінальному runtime-образі: 5 повторних пошуків;
  успішний і порожній результат; null як помилка протоколу з доступною формою;
  HTML зі snippet залишається текстом; відсутність Vue показує видиму помилку.
  Заблоковано всі зовнішні HTTP-адреси, звернень до них — 0.
- Знайдену браузерну відмінність від Node (`fetch` потребує правильного
  receiver) виправлено через bind(globalThis) і покрито окремою регресією.
- Full: 12 000 `.txt`, 2 462 028 386 байтів; генерація 110,23 с,
  повторне використання 0,307 с, SHA-256-перевірка 3,38 с.
- Автоматичне індексування full чотирма потоками: 23,217 с,
  `/api/stats` повернув рівно 12 000 (без manifest.json).
- Підсумковий запуск через Compose: автоматична індексація 15,965 с,
  smoke успішний, 10 результатів для whale, keyword time_ms=5.

  412 492 байти, готовність без ручної індексації. Після restart файли
